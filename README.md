# tg-ai

Локальный Telegram-бот: aiogram + LangChain + MLX, архив и сводки в SQLite.
Читает текст и подписи к медиа в разрешённых чатах, отвечает на @упоминание
или reply на своё сообщение. В разрешённой личке отвечает на каждое сообщение.
Фото, аудио и вложения пока не распознаёт. Векторный поиск пока не подключён.

## Запуск

1. Установите зависимости: `uv sync`.
2. Скопируйте `.env.example` в `.env`, задайте токен BotFather и числовые ID
   разрешённых чатов: `ALLOWED_CHAT_IDS=[-1001234567890]`.
   ID можно посмотреть в обновлениях Bot API до запуска polling;
   одновременно два polling-процесса для одного токена запускать нельзя.
3. В BotFather отключите Group Privacy и повторно добавьте бота в группу.
4. В отдельном терминале запустите уже установленный MLX-сервер:

```bash
uv run mlx_vlm.server \
  --model mlx-community/gemma-4-E4B-it-qat-4bit \
  --host 127.0.0.1 --port 8080
```

MLX устанавливается в своём окружении; он не является зависимостью бота.

5. Запустите бота из папки проекта:

```bash
uv run tg-ai
```

Для остановки — Ctrl+C. Mac и оба процесса должны оставаться включёнными.
Не запускайте Hermes gateway с этим же токеном одновременно.

## Память

Оригиналы сообщений и ответы бота хранятся в `data/bot.sqlite3`.
Группы и темы изолированы. Повторно доставленные сообщения не дублируются.
Когда свежая история превышает RECENT_BYTES, старые сообщения порциями
BATCH_BYTES передаются модели для обновления сводки. Последнее сообщение
остаётся в свежем контексте. SUMMARY_BYTES ограничивает размер сводки.
Сводка и граница обработанного блока сохраняются атомарно только после
успешного ответа модели. Версии сводок и исходный архив не удаляются.

Лимиты — **байты UTF-8, не точные токены Gemma**. Очень длинный одиночный
фрагмент обрезается только для модели, оригинал остаётся в базе.
Обрезка сводки может терять детали. Поиск по архиву и точный токенизатор —
следующий этап. Архив на диске растёт; автоматического удаления пока нет.

Запросы обрабатываются последовательно: сжатие может задержать ответ.
Ошибки модели не продвигают границу сводки; следующая реплика повторит сжатие.
Это MVP, без гарантированной очереди повторной отправки после аварии.
Редактирование и удаление Telegram-сообщений пока не синхронизируются.
История до добавления бота автоматически не загружается.

## Локальность

LLM endpoint разрешён только на loopback. Внешних моделей и fallback нет.
LangSmith tracing выключен при запуске. Telegram всё равно получает сообщения
через свою инфраструктуру. `.env` и `data/` исключены из Git.
Содержимое сообщений и ответы LLM не пишутся в прикладной лог.

SYSTEM_PROMPT в `.env` позволяет изменить характер бота.
Инструменты выполнения команд и доступ к файлам компьютера боту не выданы.

## Проверка

```bash
uv run python -m unittest discover -s tests -v
```

Тесты работают без Telegram-токена и без запущенной модели: проверяют изоляцию,
дедупликацию, сжатие, сохранность архива при ошибке и упоминания после emoji.

При генерации ответа история передаётся отдельными ролями user/assistant.
Последнее обращение содержит цитату reply из Telegram (либо из архива того же
чата и темы). Цитата сохраняется отдельно от текста сообщения. При обновлении
бота колонка reply_context добавляется в существующую базу автоматически.
Свежая история отбирается целыми репликами; слишком длинное последнее
обращение и его цитата ограничиваются по размеру отдельно.

## Поиск и чтение сайтов

`WEB_ENABLED=true` (по умолчанию) включает инструменты LangChain `web_search`
и `read_webpage`. Например: «@бот найди свежие новости о MLX и дай источники»
или «@бот прочитай https://example.com и кратко перескажи».
Поиск использует DDGS с явно выбранным DuckDuckGo backend; ключ не нужен.
Сервер MLX должен возвращать стандартные OpenAI `tool_calls` для Gemma.
Просто печатать название инструмента в тексте недостаточно — такой текст не
исполняется. Сжатие памяти инструменты не использует.

За один ответ разрешено до четырёх вызовов, выдача ограничена пятью результатами.
Чтение поддерживает публичные HTML/text страницы, без JavaScript и PDF,
с таймаутами, проверкой DNS/редиректов и ограничениями размера.
Локальные адреса и нестандартные порты запрещены.
В логах видны названия вызванных инструментов и типы ошибок, без запросов
и содержимого страниц. DuckDuckGo может ограничивать частоту запросов.

Модель по-прежнему локальная, но поисковый запрос передаётся DuckDuckGo,
а URL — посещаемому сайту. Инструкция модели запрещает отправлять историю
и секреты; это не жёсткий фильтр данных. Для полностью отключённого веб-доступа
установите `WEB_ENABLED=false` и перезапустите бота.

## Зрение и самостоятельное участие

Фото Telegram и изображения-документы JPEG/PNG/WebP обрабатываются локальной
мультимодальной моделью через MLX `/v1/chat/completions`. Картинка уменьшается
до 1280px, отправляется inline (без URL с токеном Telegram), затем её описание
сохраняется в истории с пометкой о возможных ошибках. Ответ строится по описанию:
это не точное OCR и может упускать мелкие детали. Оригинал на диск не пишется.
Лимиты: 10MB и 25 мегапикселей. Альбомы обрабатываются по отдельным сообщениям.
Если сервер не поддерживает image_url, бот сохраняет отметку об ошибке, а не
придумывает содержимое. `VISION_ENABLED=false` отключает распознавание.

`PROACTIVE_ENABLED=true`: кроме ответов на обращения бот периодически спрашивает
модель, стоит ли вступить в беседу. Решение REPLY/RANDOM/SILENT видно в логах
как mode=reply/random/silent. Нераспознанное решение означает молчание.

По умолчанию: минимум 3 сообщения людей, минимум 90 секунд после своей реплики,
проверка уместности не чаще раза в 30 секунд. При проверке с вероятностью 0.08
модели разрешается выбрать спонтанную шутку; это НЕ 8% всех сообщений и не
гарантирует отправку. Модель может выбрать молчание. Прямые обращения обходят
эти ограничения. Состояние пауз раздельное по чатам/темам, сбрасывается при рестарте.

Самостоятельные реплики возникают только на новые сообщения людей; таймера,
пишущего в пустой чат, нет. Бот игнорирует других ботов. Сжатие, зрение,
решение и ответ пока последовательны, поэтому фото увеличивает задержку.
Изменить настройки можно через переменные из `.env.example`.

Характер по умолчанию стал разговорнее: короткие реплики, допустимы мат,
сарказм и абсурдные шутки. Если SYSTEM_PROMPT задан в вашем `.env`, он сохраняет
приоритет над новым характером. Изменения не снимают ограничения самой модели.

Для совместимости с сервером, отдающим Gemma-вызовы в обычном content,
бот распознаёт отдельный полный вызов вида
`web_search{query:<|"|>запрос<|"|>}` или `read_webpage{url:<|"|>URL<|"|>}`.
Он преобразуется в структурированный tool_call и проходит обычные лимиты
и проверки. Примеры внутри прозы и произвольные функции не исполняются.
Нераспознанный служебный формат заменяется сообщением об ошибке.

Регион DuckDuckGo выбирается явно: `auto` → `ru-ru` при кириллице в запросе,
иначе `wt-wt` (весь мир). Это эвристика для русского чата, а не полноценное
определение языка. Модель также может выбрать ru-ru/wt-wt/us-en/uk-en.
Лог `DuckDuckGo search: script=cyrillic region=ru-ru selection=auto` показывает
реальные параметры перед сетевым запросом. Сам запрос не логируется.
Регион влияет на ранжирование, но не ограничивает язык результатов строго.

## Форматирование ответов

Обычный Markdown модели преобразуется в Telegram entities: жирный, курсив,
зачёркивание, ссылки HTTP(S), inline-код и блоки кода. Заголовки становятся
жирным текстом, списки — строками с маркерами. Разбиение длинных ответов
сохраняет форматирование и учитывает UTF-16/emoji. MarkdownV2 напрямую
модели доверять не нужно — спецсимволы не вызывают ошибок парсинга Telegram.
Схемы пока текстовые в блоках кода. Mermaid не рендерится; Markdown-картинки
превращаются в подпись со ссылкой, не отправляются как фото.

## Rich Messages (новый основной режим)

По умолчанию `RICH_MESSAGES_ENABLED=true`: ответ передаётся через
`sendRichMessage` / `InputRichMessage(markdown=...)`. Поддерживаются заголовки,
таблицы, формулы и изображения отдельными блоками между абзацами:

```markdown
# Пример

| Параметр | Значение |
| --- | --- |
| Модель | Gemma |

![Описание](https://example.com/real-image.png)

Текст после изображения.
```

URL в примере — шаблон; для реальной отправки нужен доступный URL изображения.
Генератор изображений и Mermaid-рендерер не подключены. Изображения по URL
загружает Telegram, они являются частью сообщения; это не локальная генерация.

Обычное оформление из предыдущего раздела теперь запасное: при явном отказе
API или исходнике больше 32000 байт отправляются обычные части с entities.
Это консервативный лимит исходника; Telegram допускает до 32768 символов
rich-текста. При сетевом таймауте автоматический fallback не выполняется,
чтобы не продублировать уже доставленное сообщение.
`RICH_MESSAGES_ENABLED=false` возвращает прежний режим.

Собственные ответы сохраняются в SQLite как исходный Markdown, входящий
rich-текст и цитаты извлекаются из блоков. Вложенные изображения входящего
rich-сообщения пока не передаются зрению (обычные фото поддерживаются).

## Очередь и задержки

Приём Telegram-сообщений теперь только сохраняет их и ставит в очередь.
Один модельный worker обрабатывает прямые обращения раньше фоновых сообщений;
порядок прямых обращений сохраняется. Для каждого ответа фиксируется ID исходной
реплики, поэтому новые сообщения не подменяют вопрос во время ожидания.
Решения о самостоятельном участии объединяются: оценивается только последнее
сообщение накопившейся пачки, а не каждое промежуточное.

Сжатие выполняется только после двух секунд пустой очереди, по одному блоку.
Новые поступления не включаются в уже начатую сводку. Начатый запрос к MLX
не прерывается: прямое обращение может дождаться текущей генерации/блока сжатия.
Очередь в памяти, после аварийного перезапуска незавершённые задания автоматически
не восстанавливаются; оригиналы уже принятых сообщений остаются в SQLite.

Зрение вызывается только для фото или поддерживаемого изображения-документа.
Текст, ссылки и обычные документы не запускают зрение. Base64 освобождается
на стороне бота сразу после описания; память MLX управляется отдельным процессом.
Логи `Timing: stage=queue/vision/decision/answer/summary/total ... elapsed=...s`
показывают задержки без содержимого переписки. Answer включает вызовы веб-инструментов.
Эта секция заменяет прежнее описание полностью последовательного приёма.

Фоновые задачи ограничены: сжатие запускается после 30 секунд без новых
сообщений и не чаще одного раза в 180 секунд глобально. На изменившийся чат
обрабатывается один блок; задача сама себя повторно не ставит. Большой архив
сжимается постепенно при дальнейшей активности, исходники не удаляются.
Лимиты генерации: решение об участии — 16 токенов, сводка — 256,
описание изображения — 256. Ответы сохраняют MAX_OUTPUT_TOKENS.
Это заменяет прежнее поведение с повторным сжатием каждые две секунды.

Поисковик теперь задаётся явно: `SEARCH_BACKEND=duckduckgo` или `brave`.
`bing` допустим в конфигурации, но ddgs 9.16.1 отключает этот движок;
бот проверяет доступность и не позволяет библиотеке молча перейти на auto.
Логи и результаты инструментов содержат реальный выбранный backend.
В проверке 2026-11-05 DuckDuckGo и Brave дали таймауты: рабочий альтернативный
поисковик не подтверждён, поэтому настройка по умолчанию не менялась.

По умолчанию включён `SEARCH_BACKEND=auto`: Yahoo → Brave → DuckDuckGo →
Startpage → Mojeek, только движки, реально доступные в установленной ddgs.
Последний успешный движок пробуется первым. За запрос максимум 3 попытки
по 8 секунд ожидания; движки с ошибками пропускаются на 5 минут.
В логах `Search attempt` / `Search succeeded` виден конкретный движок.
Это наше явное переключение, а не скрытый fallback библиотеки.
Наличие fallback не гарантирует доступность сайтов из текущей сети.

Rich Messages используются только для сложной структуры: заголовков, таблиц,
блоков кода, списков, цитат, изображений и формул. Обычные разговорные ответы,
включая отдельные жирные/курсивные слова и ссылки, отправляются стандартным
sendMessage с entities. Это сохраняет обычное оформление реплик в клиенте.

Регион поиска больше не задаётся ботом: `web_search` принимает только `query`,
а вызов DDGS не содержит `region` (используется значение по умолчанию библиотеки).
Прежние инструкции о ru-ru/wt-wt выше не применяются. Старый аргумент region
в вызовах модели игнорируется для совместимости с сохранённой историей.
